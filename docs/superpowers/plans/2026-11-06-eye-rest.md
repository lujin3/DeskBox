# 护眼定时休息（Eye Rest）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 DeskBox 增加双档护眼定时休息：小休（默认 20 秒/每 20 分钟）+ 大休（默认 5 分钟/每 4 次小休），到点全屏遮罩盖住所有显示器强制休息，显示倒计时与随机休息建议，可跳过；大休前 30 秒发系统通知预告。

**Architecture:** 纯逻辑休息策略（`EyeRestBreakPolicy`，无 WinUI 依赖、可单测）驱动 1 秒 `DispatcherQueueTimer` 会话（照抄 `TodoReminderService` 生命周期模式）；到点由 App 层回调弹出 `EyeRestOverlayWindow`（照抄 `DisplayIdentifyOverlayWindow` 无边框全屏模板，每屏一窗）。设置走第 14 个 `*SettingsSlice` + 协调器（照抄 `TodoSettingsCoordinator`），运行时租约走 `FeatureRuntimeRegistry`（照抄 `TodoReminderRuntime`）。所有新 UI 文案进 13 语言 JSON。

**Tech Stack:** WinUI 3 / Windows App SDK（net10.0-windows10.0.22621.0）、xUnit 2.5.3、System.Text.Json source-gen。

**Spec:** 本对话已确认的设计（无独立 spec 文档）；本计划即唯一规格来源。

```csharp
internal enum EyeRestBreakKind { Mini, Long }

internal enum EyeRestBreakEventKind { None, BreakDue, BreakImminent, BreakEnded }

/// <summary>一次 tick 产生的事件；BreakDue 时 Remaining=休息时长，BreakEnded 时 Remaining=零。</summary>
internal sealed record EyeRestBreakEvent(
    EyeRestBreakEventKind EventKind,
    EyeRestBreakKind BreakKind,
    TimeSpan Remaining);

/// <summary>已验证的计划值：分钟/秒已换算为 TimeSpan；由调用方（协调器）钳制后传入。</summary>
internal sealed record EyeRestBreakSchedule(
    TimeSpan WorkInterval,
    TimeSpan MiniBreakDuration,
    TimeSpan LongBreakDuration,
    int LongBreakEveryMiniBreaks,
    TimeSpan LongBreakLeadTime);

internal sealed class EyeRestBreakScheduleFactory
{
    // 输入分钟/秒的原始设置值，内部换算+钳制（见 Global Constraints 的默认与边界），
    // 返回 EyeRestBreakSchedule；LongBreakEveryMiniBreaks 钳制到 [1,12]。
    public static EyeRestBreakSchedule Create(
        int workIntervalMinutes, int miniBreakSeconds,
        int longBreakMinutes, int longBreakEveryMiniBreaks) { … }
}

internal sealed class EyeRestBreakPolicy
{
    public EyeRestBreakPolicy(EyeRestBreakSchedule schedule);
    public EyeRestPhase Phase { get; }             // Work | MiniBreak | LongBreak
    public TimeSpan Remaining { get; }             // 当前阶段剩余
    public EyeRestBreakKind NextBreakKind { get; }
    public int MiniBreaksSinceLongBreak { get; }   // 自上次大休以来的小休次数（开始时即计数）
    public EyeRestBreakEvent Tick(TimeSpan delta); // 推进并自动状态迁移，返回本 tick 事件
    public void SkipBreak();                       // 提前结束当前休息（计数不回退）
    public void ForceBreak();                      // 立即按 NextBreakKind 开始休息（托盘「立即休息」）
}
internal enum EyeRestPhase { Work, MiniBreak, LongBreak }
```

- 语义细节（实现必须遵守）：
  - `Tick` 在 Work 阶段累计推进；到点自动迁入休息阶段（计数在**开始**时发生：小休 `MiniBreaksSinceLongBreak++`，大休清零）并返回 `BreakDue(kind, 休息时长)`；休息阶段到点自动迁回 Work（剩余=完整工作间隔）并返回 `BreakEnded`；否则返回 `None` 事件（`Remaining` 反映最新剩余量）。
  - Work 阶段且 `NextBreakKind == Long` 且剩余首次 ≤ `LongBreakLeadTime` 时返回一次 `BreakImminent(Long, remaining)`；本工作周期内不重发；小休前不发。
  - 单次 delta 大于剩余量：只产生一个事件（钳到边界），不连发。
  - `SkipBreak` 仅在休息阶段有效（Work 阶段调用为 no-op），效果=立即 `BreakEnded` 语义（返回值 void；状态直接迁回 Work）。
  - `ForceBreak` 仅在 Work 阶段有效：立即按 `NextBreakKind` 迁入休息（同计数规则）。

```csharp
namespace DeskBox.Services;

/// <summary>1 秒 DispatcherQueueTimer 会话；UI 线程创建与回调（照抄 TodoReminderService 的线程模型）。</summary>
public sealed class EyeRestTimerService : IDisposable
{
    public EyeRestTimerService(EyeRestRuntimeSettings settings, DispatcherQueue? dispatcherQueue); // 测试用 internal ctor 可注入无队列模式
    internal event Action<EyeRestBreakEvent>? EventRaised;   // App 订阅：BreakDue→盖屏；BreakImminent→通知；BreakEnded→撤屏
    internal void TickOnce();                                  // DispatcherQueueTimer.Tick 的可测入口（1 秒一次）
    public void Start();                                       // 幂等；未启用则不建 timer
    public void Refresh(EyeRestRuntimeSettings settings);     // 设置变更：非休息中重建策略；休息中先完成当前休息
    public void SkipCurrentBreak();                            // 托盘/遮罩「跳过」→ policy.SkipBreak + 撤屏事件
    public void ForceBreakNow();                               // 托盘「立即休息」→ policy.ForceBreak + 盖屏事件
    public void Dispose();                                     // 停 timer，幂等
}
```

- 事件投递细节：`TickOnce` 推进 policy；休息阶段每 tick 还需对外广播剩余量以驱动遮罩倒计时——用 `EventRaised(BreakDue/None…)` 不好表达，改为**两个**通知：`internal event Action<EyeRestBreakEvent>? EventRaised;` + `internal event Action<TimeSpan>? BreakCountdown;`（仅休息阶段、每 tick 发当前剩余）。App 层把 `BreakCountdown` 接到遮罩 `UpdateAllRemaining`。
- `Refresh` 语义（Review Focus #4）：休息中收到新设置 → 保存待用，当前休息照常结束，`BreakEnded` 后的下一个 tick 起用新计划重建 policy（工作剩余重置为完整间隔，预告去抖位复位）。
- [ ] **Step 1: 写失败测试**（`internal ctor` 传 `dispatcherQueue: null`，手动调 `TickOnce`）：
  - 默认计划 20 次 1 秒 tick（用 1 分钟工作/5 秒小休的小计划）依次产生 `BreakDue` → 休息 tick 序列发 `BreakCountdown` 递减 → `BreakEnded`；
  - `SkipCurrentBreak` 立即 `BreakEnded`、计数不回退（后续节奏证明）；
  - `ForceBreakNow` 工作中立即 `BreakDue`；
  - 休息中 `Refresh` 不打断、结束后新计划生效；
  - `Start` 在 `Enabled=false` 时不建 timer（`Refresh(Enabled=true)` 后 TickOnce 才有事件）；
  - `Dispose` 幂等、之后 TickOnce 无事件。
